## README gaps a stranger would hit (numbered)

1. Neither `setup.sh`, `setup.ps1` nor the manual instruction mentions a
   virtual environment. All of them `pip install` into whatever `python` is
   first on PATH. It worked here only because this image's Python has no PEP 668
   marker and I ran as root (pip warned about installing as root). On stock
   Ubuntu 24.04 or Debian, system pip normally refuses with
   "externally-managed-environment". That is expected platform behaviour, but I
   did not reproduce it on this VM.
2. `setup.sh` calls `python`, not `python3`. Stock Ubuntu has no `python`
   unless `python-is-python3` is installed or a venv is active. It existed on
   this image.
3. **`director hooks fo2-compile dialogue.mara.json` fails as written (exit 2).**
   `hooks scaffold fallout2_wr` writes the file to
   `./fallout2_wr-pack/dialogue.mara.json`. The README example should use that
   path.
4. `hooks scaffold` writes `fallout2_wr-pack/` and `dmip_isr-pack/` into the
   current directory, which is the repo root if you follow the README. These are
   not in `.gitignore`, so `git status` is dirty afterwards. The README does not
   say where the scaffold output goes.
5. There are two `.env` locations. `setup.sh` copies `.env.example` to
   `./.env` in the repo and tells you to "add your API keys" there. `director
   init` reports `env file: /root/.director2/.env` and creates that one too.
   `config.load_dotenv` reads `cwd/.env`, then `~/.director2/.env`. So keys put in
   the repo `.env`, as setup.sh suggests, only apply when `director` runs from
   the repo directory. The README says only "Set API keys in `.env`".
6. The discovery-loop section lists `evolve run isr_placement` and `isr_multi`
   with no caveat. Offline they print `VERDICT: no_candidate` (0 of 6 correct),
   which a stranger could read as a failure. One line saying that only `topk` is
   meaningful on the mock would prevent that.
7. `director tasks / modules / risks / history` is shorthand for four separate
   commands, not one command. It is obvious to most readers, but it cannot be
   copied and run.
8. The `evolve domains` comment ends with "...", which suggests more domains.
   There are exactly three.
9. The CI test step is `python -m pytest -q`, and `pyproject.toml` already sets
   `addopts = "-q"`. The doubled `-q` suppresses the "541 passed" summary line,
   so the CI log never shows the number the README claims (it shows only dots).
   The README's own command, `python -m pytest`, does print "541 passed".
10. Observation, not a claim: `finalize` succeeded with 1 of 4 tasks done and a
    packet still open. Afterwards, `status` said "finalized" but still printed
    "next: director decide …". The README does not say whether finalizing
    early is intended.
11. The README never says to clone the repository or `cd` into it before
    running `bash setup.sh`. It is implied, but it is a step a stranger has to
    infer.
